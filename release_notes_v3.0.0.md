### Релиз v3.0.0 — Модуль «REST API и JSON-интеграция»

Третий крупный релиз модульной конфигурации **«IT-Inventory & Warehouse 1C»** на платформе **«1С:Предприятие 8.3»**.  
В рамках релиза реализован слой внешней интеграции: REST API на базе стандартного объекта метаданных `HTTP-сервис`, сериализация/десериализация JSON, программное создание и проведение складских документов, а также встроенный эмулятор REST-клиента.

---

#### 📦 Что нового в релизе v3.0.0:

1. **HTTP-сервис `СкладAPI` (Metadata & Routing):**
   - Корневой URL: `warehouse` (полный путь: `/hs/warehouse/...`).
   - Настроены шаблоны URL (URL Templates) и обработчики HTTP-методов:
     - `GET /warehouse/api/v1/balance` ➔ метод `ОстаткиПолучитьОстатки`.
     - `POST /warehouse/api/v1/issue` ➔ метод `СписаниеСоздатьСписание`.

2. **Эндпоинт GET: Экспорт остатков в JSON:**
   - Выполняет запрос к виртуальной таблице регистра накопления `РегистрНакопления.ОстаткиКомплектующих.Остатки`.
   - Сериализует массив структур в JSON (`ЗаписьJSON`, `ЗаписатьJSON`) с явным кодированием в UTF-8 без Byte Order Mark (BOM).
   - Возвращает `HTTP 200 OK` с заголовком `Content-Type: application/json; charset=utf-8`.

3. **Эндпоинт POST: Внешняя заявка на списание комплектующих:**
   - Принимает входящее тело запроса (`ПолучитьТелоКакСтроку("UTF-8")`).
   - Десериализует JSON в дерево объектов (`ЧтениеJSON`, `ПрочитатьJSON`).
   - Валидирует справочные данные: поиск по наименованию склада, сотрудника и позиций номенклатуры с контролем заполнения.
   - Программно создаёт экземпляр документа `Документы.СписаниеКомплектующих.СоздатьДокумент()`, заполняет табличную часть и инициирует транзакционное проведение (`РежимЗаписиДокумента.Проведение`).
   - При успехе: возвращает `HTTP 201 Created` с присвоенным номером проведённого документа.
   - При ошибке валидации или нехватке остатков: перехватывает исключение и возвращает `HTTP 400 Bad Request` с диагностическим описанием ошибки.

4. **Интеграция с ACID-контролем остатков и блокировками:**
   - При вызове POST-эндпоинта документ автоматически проходит через ранее реализованный механизм управляемых блокировок (`БлокировкаДанных`) и запрос к остаткам на `МоментВремени()`.
   - При попытке списать больше остатка транзакция проведения гарантированно откатывается (`Отказ = Истина`).

5. **Сервисная обработка `ТестированиеAPI` («Эмулятор REST-клиента»):**
   - Разработан встроенный интерактивный стенд для тестирования интеграционных сценариев прямо в режиме «1С:Предприятие» (без необходимости публикации на веб-серверах Apache / IIS).
   - **GET-тест:** запрос и визуализация текущих остатков с автоформатированием JSON (pretty-print).
   - **POST-тест (201 Created):** отправка валидной заявки, фиксация списания в регистре остатков.
   - **POST-тест (400 Bad Request):** отправка заявки с превышением остатка, перехват сообщений из очереди `ПолучитьСообщенияПользователю()` и наглядный вывод точной нехватки в интерфейс.
