# IT-Inventory & Warehouse 1C (Учёт техники и склад комплектующих)

Комплексный пет-проект по разработке модульной конфигурации на платформе **«1С:Предприятие 8.3»** (управляемое приложение).  
Проект ведется разработчиком с бэкграундом в **C++** для практического освоения архитектуры платформы 1С, метаданных, транзакционной модели проведения, управляемых блокировок и аналитики СКД.

---

## 🎯 Назначение конфигурации

Комплексная автоматизация IT-отдела компании:
1. **Инвентаризация оборудования:** учёт единиц техники, закрепление за сотрудниками, контроль жизненного цикла и история состояний.
2. **Склад комплектующих и расходников:** партионный учет запасов (SSD, RAM, кабели), поступление, списание, строгий транзакционный контроль отрицательных остатков и ведомость остатков/оборотов.

---

## 🏗 Архитектура решения

### 1. Модульность и подсистемы (Subsystems)
Конфигурация разделена на функциональные подсистемы с независимым командным интерфейсом:
- **`Инвентаризация`** — учет парка техники и закрепление за сотрудниками.
- **`Склад`** — складской количественный учет комплектующих и расходных материалов.

### 2. Справочники (Master Data)
- **`Сотрудники`** — персонал (`ФИО`, `Должность`, `Email`).
- **`Оборудование`** — штучная техника (`Модель`, `ТипОборудования`, `СерийныйНомер`, `ИнвентарныйНомер`).
  - *Оптимизация:* включена СУБД-индексация полей `СерийныйНомер` и `ИнвентарныйНомер`, настроен быстрый поиск (`Ввод по строке`).
- **`Склады`** — места хранения (`Основной склад`, `Серверная`).
- **`Номенклатура`** — комплектующие и расходники (`Наименование` до 100 символов, `Артикул`).

### 3. Перечисления (Enums)
- **`ТипыОборудования`** (`Ноутбук`, `Монитор`, `СистемныйБлок`, `Периферия`).
- **`СостоянияОборудования`** (`ВЭксплуатации`, `НаСкладе`, `ВРемонте`, `Списано`).

### 4. Документы (Transactions / Events)
- **`ВыдачаОборудования`** — передача техники сотруднику:
  - Шапка: `Сотрудник`, `Комментарий`, реквизиты даты/номера.
  - Табличная часть: `СписокОборудования`.
  - Модуль объекта: валидация в `ОбработкаПроверкиЗаполнения` (контроль обязательных полей, подсветка UI через `СообщениеПользователю`, дедупликация через `Свернуть()`).
  - Автозаполнение: точное системное время при создании.
- **`ПоступлениеКомплектующих`** — оприходование расходников на склад:
  - Шапка: `Склад`. Табличная часть: `Комплектующие` (`Номенклатура`, `Количество`).
  - Формирует приходные движения (`+ Приход`) в регистр накопления.
- **`СписаниеКомплектующих`** — выдача/списание расходников:
  - Шапка: `Склад`, `Сотрудник`. Табличная часть: `Комплектующие`.
  - **Транзакционный контроль остатков:** перед записью расхода выполняется запрос к виртуальной таблице остатков на `МоментВремени()`. При попытке списать больше фактического наличия транзакция отменяется (`Отказ = Истина`) с выводом точной нехватки.
  - **Защита от Data Race:** вызов `БлокировкаДанных` с исключительным режимом блокировки по измерению `Склад` и списку номенклатуры.

### 5. Регистры (State & Balances)
- **Регистр сведений `СостояниеОборудования`** (Периодический, режим записи: *Подчинение регистратору*):
  - Измерения: `Оборудование`. Ресурсы: `Сотрудник`, `Состояние`.
  - Автоматический откат движений при отмене проведения документов (ACID).
- **Регистр накопления `ОстаткиКомплектующих`** (Вид: *Остатки*):
  - Измерения: `Номенклатура`, `Склад`.
  - Ресурсы: `Количество` (число 15.3).
  - Поддерживает автоматический пересчет итогов СУБД для быстрых срезов остатков.

### 6. Печатные формы
- **«Акт приёма-передачи техники»** — параметрический табличный документ (`ТабличныйДокумент`), формируемый процедурой печати в модуле менеджера с экспортом в PDF/Excel.

### 7. Аналитическая отчётность (СКД / OLAP)
- **Отчет «Закрепленное оборудование»**:
  - Источник: виртуальная таблица `РегистрСведений.СостояниеОборудования.СрезПоследних`.
  - Иерархическая группировка: `Сотрудник` ➔ Детализация по девайсам с подсчетом агрегата `Количество`.
- **Отчет «Ведомость по остаткам комплектующих»**:
  - Источник: виртуальная таблица `РегистрНакопления.ОстаткиКомплектующих.ОстаткиИОбороты`.
  - Бухгалтерский баланс: `Начальный остаток` ➔ `Приход` ➔ `Расход` ➔ `Конечный остаток`.
  - Многоуровневые итоги: `Склад` ➔ `Номенклатура`.

### 8. Интеграция и REST API (HTTP Services & JSON)
- **HTTP-сервис `СкладAPI`** (Корневой URL: `warehouse`):
  - `GET /warehouse/api/v1/balance` — выгрузка текущих остатков товаров на складах в формате JSON.
  - `POST /warehouse/api/v1/issue` — прием внешней заявки на списание, парсинг JSON, программное создание и проведение документа `СписаниеКомплектующих` с транзакционным контролем остатков и блокировками (коды ответа `201 Created` / `400 Bad Request`).
- **Сервисная обработка `ТестированиеAPI` («Эмулятор REST-клиента»)**:
  - Интерактивный инструмент для проверки REST API, парсинга JSON и тестирования создания документов прямо в режиме «1С:Предприятие» без развертывания веб-серверов Apache/IIS.
